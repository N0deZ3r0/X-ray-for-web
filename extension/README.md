# Расширение

Google Chrome, Manifest V3, минимальная версия 119.

Сборка **Э5**. Наблюдаются 67 поверхностей отпечатка в восьми группах и
исходящее из двух независимых источников: обёртки внутри страницы и `webRequest`.
Их несовпадение и есть детектор обхода.

Разбор формата подключён для GA4, Meta Pixel, Яндекс.Метрики и Вебвизора: поля
показаны словами, а неопознанные — как неопознанные, со счётчиком. Все четыре —
декларации-данные; движок ради Метрики получил две возможности (извлечение из
пути адреса и распаковку вложенного `browser-info`), но кода разбора в нём
по-прежнему нет.

## Установка

1. `chrome://extensions`
2. Включить «Режим разработчика» (переключатель справа сверху)
3. «Загрузить распакованное расширение» → выбрать папку `extension`
4. Открыть боковую панель кнопкой расширения на панели инструментов

## Как записать

1. Открыть сайт, например стенд на http://localhost:8080
2. В панели нажать «Записать этот сайт»
3. Выдать разрешение на этот origin
4. Вкладка перезагрузится сама — иначе обёртки не успеют встать до скриптов
   страницы (предел 9 из [../docs/06-limits.md](../docs/06-limits.md))

Галочка «включая сторонние фреймы» запрашивает доступ ко всем адресам. Без неё
кросс-origin фреймы не наблюдаются: у них свой origin и свой набор обёрток.

## Что где

| Путь | Роль |
|---|---|
| `manifest.json` | Разрешения. `host_permissions` пуст намеренно: доступ запрашивается по сайту, по команде |
| `instrument/main.js` | MAIN world. Обёртки, снятие стека, бюджет, схлопывание, мост |
| `collector/isolated.js` | ISOLATED world. Только переносит наблюдения и считает потери |
| `background/index.js` | Service worker. Слушатели регистрируются синхронно на верхнем уровне |
| `background/session.js` | Журнал, сверка источников, детектор обхода |
| `background/webrequest.js` | Сетевой источник: тела запросов и имена ушедших кук |
| `background/parsers/` | Движок разборщиков и декларации как данные |
| `background/facts.js` | Свод «Что о вас узнали»: факт только со ссылкой на события |
| `background/export.js` | Экспорт с редакцией по умолчанию |
| `ui/panel.*` | Боковая панель |

## Разрешения этой сборки

`storage`, `scripting`, `sidePanel`, `tabs`, `webRequest` — и
`optional_host_permissions` на все адреса, которые запрашиваются по требованию.

`webRequest` появился именно на Э2 и ни днём раньше: объявлять право, которым
сборка не пользуется, значит пугать пользователя зря. Он наблюдательный —
в MV3 блокирующий режим недоступен, да и прибор ничего не блокирует.

Это самая политически хрупкая часть стека: Google периодически пересматривает
наблюдательный `webRequest`. Если его отберут, прибор теряет внешний источник,
а с ним детектор обхода и уровень доверия `confirmed`. Риск принят осознанно.

## Отладка без переустановки

Стенд отдаёт файлы расширения по `/__ext/...`, чтобы гонять инструмент как
обычный скрипт:

```js
const s = document.createElement('script');
s.src = '/__ext/instrument/main.js';
document.head.appendChild(s);
addEventListener('__xray_v1', e => console.log(JSON.parse(e.detail)));
dispatchEvent(new CustomEvent('__xray_v1_ready'));
```

Канал живёт на `window`, а не на `document`: `document.open()` сносит слушатели
и с документа, и с окна, а таймеры переживает — на этом построено восстановление
моста во фреймах, наполненных через `document.write`.

Так проверены атрибуция, бюджет и реестр без цикла «поправил — переустановил».
В самом расширении этого пути нет.

## Проверено

### Э0, в реальном Chrome

| Критерий | Результат |
|---|---|
| Прибора нет, пока запись не включена | 0 из 4 фреймов |
| Главный документ | покрыт |
| `srcdoc`-фрейм | покрыт, значит `matchOriginAsFallback` работает |
| `about:blank` через `document.write` | покрыт после починки моста |
| Кросс-origin фрейм | покрыт при разрешении на все адреса |

Атрибуция на стенде: `canvas.toDataURL` из стороннего скрипта даёт
`http://localhost:8081/fp-basic.js:20:23` с пометкой «сторонний», из встроенного —
`http://localhost:8080/:49:22` с пометкой «встроенный». Строки и колонки сверены
с исходниками, совпадают точно.

### Э2, сверка источников

`node tests/reconciler.test.mjs` — 45 проверок в трёх порядках прихода событий
(сеть первой, изнутри первой, вперемешку), на числах стенда:

| Что | Результат |
|---|---|
| Подтверждено обоими источниками | 6 |
| Нечем проверить (WebSocket) | 1 |
| Прошло мимо инструментации | 3 |
| Ложных обходов на 34 шумовых запросах | **0** |
| Выдуманной атрибуции у обходов | нет |

Седьмым подтверждённым здесь одно время числился WebSocket. Это была ошибка:
разрешения не покрывают схему `ws`, сетевой источник его не видит вовсе, и
записывать его в «подтверждено» значило приписывать прибору зрение, которого у
него нет. Теперь у такого транспорта отдельный вердикт.

Перехват исходящего проверен на стенде: 7 запросов всеми транспортами с
атрибуцией до строки в `beacon.js`, три обхода корректно НЕ дали записи изнутри.

Цена прибора измерена отдельно, см. [../bench/perf/README.md](../bench/perf/README.md):
вызов со снятием стека — 18.1 мкс, горячий вызов — 0.155 мкс, полный бюджет
подробностей — 21.7 мс на документ. На шести реальных сайтах перехвачено от 26
до 669 вызовов, ни один не подошёл к бюджету.

### Не проверено

- **Боковая панель в настоящем Chrome — только руками.** Со стороны страницы
  она не видна, автоматизация до неё не дотягивается. Логика панели покрыта
  набором `tests/panel.test.mjs` (25 проверок) на подставном DOM: журнал,
  фильтр, предупреждение о стирании, отсутствие лишних перерисовок. Но это
  проверка логики, а не настоящего рендеринга.
- **Просадка LCP на реальных сайтах** — главный критерий Э1. Не закрыт и не
  закрываем видимостью: вкладку под автоматизацией Chrome считает скрытой и не
  отрисовывает, а разброс `load` на одном сайте достигал трёх раз. Причины и
  все замеры — в [../bench/perf/README.md](../bench/perf/README.md).
- Переживание журналом перезапуска service worker.
