# 05 — Разборщики форматов

## Проблема

GA4 и Яндекс.Метрика меняют схему быстрее, чем расширение проходит ревью в Chrome
Web Store. MV3 запрещает подгружать код, значит обновить разборщик «на лету»
нельзя.

Разборщик, который гниёт молча, хуже отсутствующего: он показывает
правдоподобную неправду.

## Решение: разборщик — это данные

Разборщики объявляются декларативным JSON, который интерпретирует встроенный
движок. Никакого исполняемого кода в декларации — ни `eval`, ни функций, ни
регулярных выражений с обратными ссылками из внешнего источника.

Два следствия:

1. Запрет удалённого кода в MV3 не нарушается — декларации это данные.
   Пользовательский или обновляемый пакет разборщиков остаётся возможен.
2. Движок один и тестируется отдельно от знаний о конкретном трекере.

## Правило неизвестного поля

**Главное правило проекта. Нарушение = баг, а не косметика.**

- Поле, отсутствующее в декларации и не подходящее ни под один шаблон,
  отображается как `неопознанное поле <имя> = <сырое значение>`.
- Оно попадает в счётчик: «разобрано 18 полей, не опознано 3».
- Счётчик виден в интерфейсе всегда, рядом с названием разборщика и датой его
  схемы.

Так интерфейс сам сообщает о своём устаревании. Когда GA4 добавит поле, человек
увидит «не опознано 4» вместо тихой лжи.

Разбор никогда не додумывает. Нет правила — нет ярлыка.

## Формат декларации

```jsonc
{
  "id": "ga4",
  "title": "Google Analytics 4",
  "version": "2026-09",          // дата знания о схеме, видна в UI
  "match": {
    "host": ["*.google-analytics.com", "analytics.google.com"],
    "path": "^/g/collect"
  },
  "extract": [
    { "from": "query" },
    { "from": "body", "format": "lines-urlencoded" }
  ],
  "fields": {
    "tid": { "label": "Идентификатор счётчика сайта", "kind": "site-id",   "confidence": "documented" },
    "cid": { "label": "Идентификатор вашего браузера", "kind": "device-id", "confidence": "documented",
             "note": "Берётся из куки _ga, срок жизни 2 года" },
    "sid": { "label": "Идентификатор сессии", "kind": "session-id", "confidence": "documented" },
    "uid": { "label": "Ваш идентификатор в системе сайта", "kind": "user-id", "confidence": "documented",
             "note": "Сайт передал собственный идентификатор пользователя — связывает визит с учётной записью" },
    "en":  { "label": "Название события", "kind": "event-name", "confidence": "documented" },
    "dl":  { "label": "Адрес страницы", "kind": "page-url", "confidence": "documented" },
    "dr":  { "label": "Откуда вы пришли", "kind": "referrer", "confidence": "documented" },
    "sr":  { "label": "Разрешение экрана", "kind": "screen", "confidence": "documented" },
    "ul":  { "label": "Язык браузера", "kind": "language", "confidence": "documented" }
  },
  "patterns": [
    { "test": "^ep\\.", "label": "Параметр события",   "kind": "event-param" },
    { "test": "^up\\.", "label": "Свойство пользователя", "kind": "user-property" }
  ],
  "unknown": "preserve"          // единственное допустимое значение
}
```

`"unknown": "preserve"` присутствует в схеме явно, чтобы намерение было записано,
а не подразумевалось. Валидатор отвергает декларацию с любым другим значением.

## Разборщики v1

### GA4 — первый и единственный в первом релизе

Адреса: `www.google-analytics.com/g/collect`, `analytics.google.com/g/collect`,
региональные `region*.google-analytics.com`.

Особенности: POST-тело содержит пачку событий, разделённых `\r\n`, каждое —
urlencoded строка. Разбирать надо каждую отдельно, иначе пачка из 6 событий
покажется одним.

Приоритетные к объяснению поля: `cid` (идентификатор устройства), `uid`
(связка с учётной записью — сильный факт), `dl`/`dr` (маршрут), `ep.*`
(что именно вы делали).

### Две возможности движка, добавленные ради Метрики

**Извлечение из пути адреса.** Номер счётчика Метрики лежит не в параметрах, а
в пути: `mc.yandex.ru/watch/12345678`. Это ответ на вопрос «кому уходят данные»,
и терять его нельзя. В декларации:

```jsonc
{ "from": "path", "pattern": "^/watch/(\d+)", "names": ["counter"] }
```

**Распаковка вложенного параметра.** Метрика упаковывает всю начинку в один
параметр `browser-info` строкой вида `ключ:значение:ключ:значение`:

```jsonc
"nested": [
  { "param": "browser-info", "format": "colon-pairs", "title": "Что внутри browser-info" }
]
```

Внутри оказываются идентификатор браузера, разрешение экрана, часовой пояс и
язык — то есть самое содержательное. Без распаковки это был бы один
неопознанный блоб.

**Что делать при рассинхронизации.** Если в значении встретится двоеточие,
пары поедут и все последующие подписи окажутся сдвинуты на одно поле — то есть
разбор начнёт выдавать правдоподобную неправду. Движок это замечает по тому, что
очередной «ключ» перестал быть похож на ключ, и **останавливается**, отдавая
остаток одним неопознанным полем. Проверяется тестом.

### Meta Pixel — второй

Адрес: `www.facebook.com/tr`, GET и POST.

Ключевое: `ud[em]` — SHA-256 хеш адреса электронной почты, `ud[ph]` — телефона,
`ud[fn]`/`ud[ln]` — имени и фамилии. Это Advanced Matching, и это самый сильный
факт, который прибор может показать обычному человеку: «сайт отправил в Meta
хеш вашей почты». Плюс `id` (пиксель), `ev` (событие), `cd[*]` (произвольные
данные сайта), куки `_fbp` и `_fbc`.

### Яндекс.Метрика — третий

Адрес: `mc.yandex.ru/watch/<id>`.

Особенности: параметр `browser-info` — упакованная строка вида `ключ:значение:`
через двоеточия и точки с запятой; внутри `s` (экран), `w` (окно), `z` (часовой
пояс), `la` (язык), `u` (идентификатор), `c` (куки включены), тайминги.
Параметр `site-info` — JSON пользовательских параметров сайта. Куки `_ym_uid` —
идентификатор.

Отдельно: `mc.yandex.ru/webvisor/<id>` — **запись действий на странице**.
Это самостоятельный сильный факт, а не разновидность аналитики: «сайт записывает
ваши движения мыши, прокрутку и ввод». Показывается отдельной строкой.

## Как это устроено на деле

| Файл | Роль |
|---|---|
| `extension/background/parsers/engine.js` | Движок: проверка декларации, сопоставление адреса, разбор |
| `extension/background/parsers/ga4.json` | Декларация GA4 |
| `extension/background/parsers/meta-pixel.json` | Декларация Meta Pixel |
| `extension/background/parsers/yandex-metrika.json` | Декларация Яндекс.Метрики |
| `extension/background/parsers/yandex-webvisor.json` | Декларация Вебвизора — отдельная, см. ниже |
| `*-bench.json` | Те же словари, но совпадают ТОЛЬКО с `localhost` — для стенда |
| `extension/background/parsers/index.js` | Реестр: читает декларации через `fetch` по `chrome-extension://` |

Декларации читаются как **данные**, а не импортируются как код. Запрет MV3 на
исполнение загруженного кода не нарушается, и тот же механизм позже примет
пакет деклараций, обновляемый без релиза движка.

Разбор идёт лениво, при обращении панели: реестр читается асинхронно, а
слушатели service worker обязаны регистрироваться синхронно.

### Что движок отвергает

Битая декларация опаснее отсутствующей — она даёт правдоподобную неправду.
Поэтому проверка отвергает декларацию, если:

- `unknown` не равно `preserve` — иначе разборщик сможет молча выкидывать поля;
- у поля нет `label`;
- у поля стоит `confidence: "guess"` — либо знаем, либо не опознано;
- нет `id`, `version` или `match.host`;
- шаблон имени не строка или длиннее 200 символов.

Отвергнутые декларации попадают в консоль service worker: молчаливая слепота
запрещена.

### Подделка под домен не проходит

`*.google-analytics.com` совпадает с `www.` и `region1.`, но **не** с
`evilgoogle-analytics.com` и не с `google-analytics.com.evil.net`. Иначе прибор
назвал бы чужой сайт Google, а это обвинение наоборот — оправдание чужого
трекера чужим именем. Проверяется тестом.

## Тесты разборщиков

## Метки на двух языках

`label`, `note` и `title` — объекты, а не строки:

```json
"cid": {
  "label": { "ru": "Идентификатор вашего браузера", "en": "Your browser identifier" },
  "kind": "device-id",
  "confidence": "documented"
}
```

Текст живёт в декларации, а не в `_locales`, потому что декларация — данные:
новый разборщик добавляется одним файлом, без правки движка и без правки
переводов. Движок языки не выбирает вовсе, он отдаёт метку как есть; выбирает
тот, кто показывает. Строка вместо объекта допустима — это значит «автор дал
один язык», и показан будет он: выдумывать перевод нельзя.

Набор `tests/i18n.test.mjs` требует обоих языков во всех декларациях, которые
лежат в репозитории.

## Наследование деклараций

Двойники для стенда (`*-bench.json`) раньше были побайтовыми копиями настоящих
деклараций — отличались тремя полями из десяти, а весили сто строк каждый. Копия,
которую надо править синхронно, это не удобство, а заведённая на будущее ошибка:
достаточно один раз поправить `ga4.json` и забыть про `ga4-bench.json`, чтобы
стенд начал проверять не то, что работает на живом сайте.

Теперь наследник объявляет только отличия:

```json
{
  "id": "ga4-bench",
  "extends": "ga4",
  "version": "2026-09",
  "match": { "host": ["localhost", "127.0.0.1"], "path": "^/g/collect" }
}
```

Слияние поверхностное и намеренно: подмешивать отдельные поля внутрь `fields`
значило бы разрешить наследнику незаметно переопределить назначение одного
параметра, а декларация должна читаться целиком.

`node tests/parsers.test.mjs` — 54 проверки. Главные:

1. **Неизвестное поле не выброшено**, показано без ярлыка, с сохранённым
   значением, и счётчик неопознанного вырос. Это тест на честность, и он важнее
   всех остальных.
2. Пачка событий GA4 разбирается на три отдельных события, а не схлопывается.
3. Доля разобранных полей на золотом образце не ниже 90%.
4. Подделка под домен не проходит.
5. Декларация с `unknown: "drop"` или с `confidence: "guess"` отвергается.
6. Стендовая декларация не может совпасть с живым сайтом.

## Замер на живом GA4

smashingmagazine.com, один маячок, 36 полей. Замер сделан внутри страницы:
наружу выносились только имена полей и числа — значения содержат настоящий
`cid` пользователя и остались на месте.

| Редакция словаря | Разобрано |
|---|---|
| Первая (25 полей) | **50.0%** — 18 неопознанных |
| После дополнения (38 полей) | **86.1%** — 5 неопознанных |

Замер на трёх сайтах после дополнения:

| Сайт | Маячков GA4 | Разобрано |
|---|---|---|
| smashingmagazine.com | 1 | 86.1% |
| css-tricks.com | 1 | 86.1% |
| freecodecamp.org | 2 | 94.4% и 85.4% |

### Неопознанные поля GA4 — рабочий список

Их семь на всю выборку. Список ведётся здесь, чтобы сокращать его
целенаправленно, а не делать вид, что его нет:

| Поле | Где встретилось |
|---|---|
| `ngs` | во всех маячках |
| `rcb` | во всех маячках |
| `_eu` | smashing, freecodecamp |
| `_ee` | smashing, css-tricks, freecodecamp |
| `ir` | smashing, freecodecamp |
| `gdid` | css-tricks |
| `gap.uat` | freecodecamp |

Подписать их по правдоподобию нельзя: это `confidence: "guess"`, и движок такую
декларацию отвергает. Пусть счётчик показывает семь, чем интерфейс покажет семь
выдумок.

### Чужой формат на том же хосте

freeCodeCamp шлёт вдобавок маячок **Universal Analytics** на `/j/collect` —
тот же хост `google-analytics.com`, другой протокол, 28 совершенно других полей
(`_v`, `a`, `t`, `vp`, `jid`, `_gid`, `cd2`, `cd5`…).

Разборщик GA4 совпадает только с `^/g/collect` и на него не среагировал. В
интерфейсе такой запрос получает подпись «формат не опознан» — и это верно.
Разобрать его словарём GA4 значило бы выдать 28 подписей, ни одна из которых не
соответствует действительности.

Первая редакция не назвала словами ровно ту группу, ради которой всё
затевалось: `uaa`, `uab`, `uap`, `uapv`, `uam`, `uamb`, `uafvl`, `uaw` —
высокоэнтропийные подсказки User-Agent, то есть архитектура, разрядность,
версия системы, модель устройства и полный список версий браузера. Счётчик
неопознанного показал дыру сразу, и в этом весь его смысл.

Остались неопознанными: `_eu`, `ir`, `ngs`, `rcb`, `_ee`. Что они означают, мне
неизвестно, а подписать их по правдоподобию — это `confidence: guess`, который
движок отвергает. Пусть лучше счётчик показывает пять, чем интерфейс покажет
пять выдумок.

**Отдельная поправка на честность.** В первой редакции почти всем полям стояло
`confidence: documented`. Это было неверно: **Google не публикует список
параметров `/g/collect` вовсе.** Документированными оставлены только те, что
известны из публичной документации gtag и наследия Universal Analytics; всё
прочее переведено в `observed`, и об этом сказано в самой декларации.

### Почему Вебвизор — отдельный разборщик

`mc.yandex.ru/webvisor/<id>` можно было бы считать разновидностью Метрики: тот
же хост, тот же счётчик. Но это **не аналитика, а запись сеанса**: движения
мыши, прокрутка, клики и ввод в поля, которые потом смотрят как видео.

Человек читает «аналитика» и думает про счётчик посещений. Поэтому у Вебвизора
своя декларация со своим названием, и свод говорит о нём отдельным фактом:
«Сайт записывает ваши действия на странице» — с оговоркой, что содержимое
записи прибору не видно.

## Что не разбираем

Домены из чужих списков трекеров без декларации не помечаются как трекеры.
Если на домен нет разборщика, запрос показывается как есть: адрес, метод,
размер, сырое тело. Прибор не говорит «это трекер» на основании чужого мнения —
это была бы та же беда, что «47 заблокированных».
